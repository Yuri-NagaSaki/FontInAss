# Bun 1.4.2 升级与性能基线

日期：2026-10-04（Asia/Tokyo）。基线提交：`7c06fd9`。本次升级到 GitHub 官方 [Bun 最新稳定版 1.4.2](https://github.com/oven-sh/bun/releases/tag/bun-v1.4.2)，官方发布日期为 2026-09-05。下载的 Linux x64 下载包已对照 release asset 的 SHA-256 校验。

## 升级范围与实现

- 本机 `bun`、Docker builder/runtime、CI、`.bun-version`、`packageManager`、`engines.bun`、两个 workspace 中的 `@types/bun` 和锁文件统一到 1.4.2。CI 从 `.bun-version` 读取版本，部署脚本同时核对镜像提交号和运行时 Bun 版本。
- 原生字体处理使用与全局请求并发一致的 Python 进程池，复用 FontTools 导入。每 worker 最多 64 个字体任务或空闲 30 秒后退出；故障、超时和服务停止时终止该进程组，包括 HarfBuzz 子进程。队列最多 32 项，保留 512 MiB 地址空间、30 秒累计 CPU、60 秒任务超时和输出预算。
- 本地存储先验证路径，再将字体路径交给 worker，避免先读入 Bun 再复制到临时文件。内存型字体来源仍可传入字节。路径验证仍拒绝目录穿越、符号链接和非文件。
- 缺字检查读取 HarfBuzz 生成的小子集 cmap，避免重复解码完整 CJK 源字体 cmap。保留原有布局闭包、轮廓、hinting、命名和 bounding box 计算；本轮字幕产物与基线逐字节一致。
- 字体列表先选择当前页再聚合字体面和全部名称，新增 `font_names(face_id)`、`font_files(created_at DESC, id)` 索引。修正搜索时只返回匹配的那一个别名的问题，提供稳定分页。
- 分享列表缓存 5 秒、处理统计缓存 1 秒，相关服务写入立即失效；日界和日志清理也使统计失效。外部绕过服务直接修改数据库时，最多等待相应 TTL。
- 后端 workspace 共用一次 TypeScript 检查，Vue 保留独立检查。新的根配置也覆盖服务端测试和基准脚本，补齐此前未被检查的测试类型。

## 对照设计

| 组别 | 代码和构建产物 | Bun | 其他依赖 |
| --- | --- | --- | --- |
| A：升级前 | `7c06fd9` 的生产镜像 | 1.4.0 | HarfBuzz 10.2.0、FontTools 4.62.1 |
| B：只升级运行时 | A 的 JS/CSS/系统层不变，仅替换 Bun 二进制 | 1.4.2 | 与 A 相同 |
| C：升级并优化 | 本次代码用 Bun 1.4.2 构建；运行镜像基于 B | 1.4.2 | 与 A 相同 |

构建耗时另外比较原始源码在 Bun 1.4.0/1.4.2 下重新构建，以及优化后的源码。HTTP 组 B 不重新编译，确保可区分运行时收益与编译产物/代码收益。

- 同一主机：8 vCPU，AMD EPYC 9645 虚拟机，Linux 6.8.0-110-generic，约 16 GiB 内存。主机上还有其他服务，未独占 CPU。
- 每轮独立 Docker 容器：3 GiB 内存、无 swap、128 个 PID 上限、2 个字幕请求并发；字体目录只读，SQLite 使用同一份在线备份的独立副本。生产数据库不参与压测写入。
- 快照 SHA-256：`f1c0414319762f40b25625afac8eb82173afd34f46b0a167cd252ebb767db134`。字体库包含 31,504 个文件、110,730 条名称。
- A/B/C 各 3 轮。全部 HTTP 负载由固定 Bun 1.4.0 客户端生成。每轮 1,097 个主请求，三组共 **9,873 个主请求**，另有预热和处理期间每 20 ms 一次的健康探针。
- 7 类字幕：拉丁文、中日韩、竖排、阿拉伯文、缺字警告、1,500 行 ASS、3 种字体的 ASS。每轮先预热文件系统和进程；未命中测试对每个请求使用不同 alias salt，确保不命中字幕结果缓存。
- 表格采用「每轮中位数的中位数」；P95 和吞吐量同样取三轮统计值的中位数。负数表示变慢。所有请求要求预期 HTTP/X-Code 和非空字幕产物，错误不会被算作吞吐量收益。

## HTTP 延迟

单位：ms。

| 工作负载 | A：升级前 | B：仅 Bun 1.4.2 | C：升级并优化 | A → C 延迟下降 |
| --- | ---: | ---: | ---: | ---: |
| 字幕处理，结果缓存未命中，1 并发 | 209.943 | 207.841 | 12.452 | 94.07% |
| 字幕处理，结果缓存未命中，2 并发 | 223.284 | 210.156 | 18.981 | 91.50% |
| 字幕处理，结果缓存命中，2 并发 | 0.471 | 0.557 | 0.345 | 26.79% |
| 健康接口，4 并发 | 0.250 | 0.252 | 0.255 | -1.69% |
| 字体列表首页，4 并发 | 2445.010 | 2399.231 | 5.460 | 99.78% |
| 分享列表，4 并发 | 8.898 | 8.501 | 4.776 | 46.32% |
| 处理统计，2 并发 | 10.465 | 10.023 | 0.235 | 97.75% |
| 字体目录统计，1 并发 | 0.296 | 0.378 | 0.437 | -47.86% |

单独升级运行时对未命中缓存的字幕处理只改善约 **1%**。主要收益来自消除 Python 启动、完整字体读取/复制和全库聚合。缓存命中与健康接口原本已低于 1 ms，百分比对调度和 JIT 状态敏感，不应据此宣称稳定收益。

字体统计的中位数从 0.296 ms 增加到 0.437 ms，P95 从 1.185 ms 增加到 2.550 ms；此次没有改善该接口，绝对差值约 0.14 ms。完整结果保留这项退化。

| 一轮混合负载耗时，秒 | 64.69 | 62.54 | 2.15 |

双并发未命中字幕吞吐量提高 **9.51 倍**；混合负载 CPU 用量下降 **96.32%**，匿名内存峰值下降 **64.24%**。混合负载的 CPU/总耗时主要受字体列表优化影响，不能解读为每个请求都有相同节省。

内存每 25 ms 从 cgroup v2 采样；匿名内存覆盖 Bun、Python 和 HarfBuzz，接近进程驻留内存但不是逐进程 RSS 之和。总内存还包含文件页缓存。短峰值可能落在采样间隔中。CPU 用量也包含额外健康探针，C 运行更快，因此收到的探针较少。

## 首请求和健康探针

以上字幕收益是工作进程已预热、结果缓存未命中的持续处理表现。C 三轮首个字体请求分别为 **115.54、142.54、123.26 ms**；工作进程空闲退出或达到回收次数后也会重新导入模块。不能将 12.45 ms 当作所有请求的冷启动延迟。

双并发字幕期间，健康探针 P95 的三轮中位数从 A 的 5.51 ms 变为 C 的 12.38 ms，最大值从 36.15 ms 变为 19.85 ms。C 的处理速率更高，主线程处理字幕和回包也更密集；同时测试窗口变短，探针总数从 712 减为 72。这项指标未改善，样本量也不同，不能宣称健康接口尾延迟提升。

## 构建与检查

构建计时采用独立的基线源码目录和依赖安装，不与 HTTP 压测同时运行。每个命令先预热一次，再计时 3 次。B 使用未修改的基线源码，只切换 Bun；C 使用优化后的根 TypeScript 配置。具体结果见测量目录中的 `build-*.json`。

| 指标 | A | B | C | A → C 下降 |
| --- | ---: | ---: | ---: | ---: |
| 完整类型检查，秒 | 19.331 | 20.263 | 8.604 | 55.49% |
| Web + 服务端构建，秒 | 7.917 | 7.461 | 7.546 | 4.68% |
| 服务端 JS bundle，字节 | 987,164 | 444,887 | 451,495 | 54.26% |

类型检查减少约 55.49%，并扩大到服务端测试和基准脚本。构建耗时减少约 4.68%；服务端 bundle 约减半主要来自 Bun 1.4.2 编译器，原始代码重编译已从 987,164 字节降到 444,887 字节。增加进程池后的 bundle 为 451,495 字节。Web JS 产物总量三组均为 631,080 字节，没有声称前端包体积改善。


## 正确性与运行约束

- 4 个 Rust CLI 集成测试通过；Chromium 检查 9 个页面、重复同名文件处理及 390 px 窄屏，无页面错误。
- 正式 Bun 1.4.2 Docker 基础镜像通过 4 组真实字体的字形位置与轮廓对比；额外连续处理 1,000 个结果缓存未命中的竖排请求，2 并发，0 错误，匿名内存峰值约 67.13 MiB、结束时约 61.94 MiB，进程/线程数峰值 22，未触发 OOM。该验证覆盖多轮 worker 回收，不等同于长期负载测试。
- 58 个 Bun 测试通过，覆盖 worker 复用、队列次序、回收、崩溃、超时、关闭、缓存失效和稳定分页，以及已有字体/字幕回归。
- **1,131 个字幕响应与 A 逐字节一致**，包含三轮单并发、双并发和缓存命中请求；缺字样本仍返回警告，没有通过跳过校验获得提速。
- 新工作进程继续遵守全局请求准入、内存/CPU、字体输出和字幕体积限制；不会无限增加并发。Native worker 只接受服务验证过的路径。
- 字体索引变更、统计日志写入、归档发布/编辑/删除的缓存失效均有测试。
- 新索引可在现有 schema 3 数据库上增量建立，没有删除或重新导入字体、凭证或分享库。部署脚本先在线备份 SQLite，并保留旧镜像；备份权限设为 0600。

## 复查方法

原始请求耗时、每轮资源统计和汇总位于 [measurements/bun-1.4.2](measurements/bun-1.4.2/)。这些文件不含原始业务数据库或凭据。

```bash
# 为每一组准备运行镜像，并提供同一份一致性 DB 快照。
# 固定客户端的 Bun 版本，按组分别保存三轮。
BENCHMARK_BUN=/path/to/bun-1.4.0/bin/bun python3 scripts/run-performance.py IMAGE SNAPSHOT_DB OUTPUT_DIR 1
# 同组再执行轮次 2、3；组目录分别命名 before、runtime-only、optimized。
python3 scripts/summarize-performance.py /path/to/group-parent

# 构建测试要求 BUN 路径所在目录中的 bun 也指向同一版本。
python3 scripts/benchmark-build.py BASELINE_REPO /path/to/bun-1.4.0/bin/bun build-before.json
python3 scripts/benchmark-build.py BASELINE_REPO /path/to/bun-1.4.2/bin/bun build-runtime-only.json
python3 scripts/benchmark-build.py CURRENT_REPO /path/to/bun-1.4.2/bin/bun build-optimized.json

python3 scripts/soak-subset.py VERIFY_CONTAINER http://127.0.0.1:3302 INPUT.ass soak.json 1000

bun run check
bun audit
```

基线针对本机字体库与这组字幕。超大字幕、复杂可变字体、远程网络、磁盘冷缓存、多实例和大规模公共流量需要各自测试；以上数据不是生产容量或 SLA 承诺。
