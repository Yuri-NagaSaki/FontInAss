# FontInAss 项目审计与优化记录

审计日期：2026-10-04（Asia/Tokyo）。基线提交：`6fb170c`。范围包含服务端、9 个能力包、Vue Web、Rust CLI、持久化、Docker 部署和运行验证。

## 结论

基线能够构建并通过原有测试，但字体生成存在实际排版错误，字幕解析、跨请求资源控制、CLI 写入和归档校验也有缺口。本次替换了自行重建字体的实现，补充针对性回归，并更新部署流程。核心协议保持 v2；数据库采用兼容性增量迁移至 schema 3，原有字体、凭证、分享和日志保留。

这份记录区分已验证结果与剩余边界，不代表所有字体、字幕方言和播放器均已穷尽测试。

## 已修复问题

### 正确性

1. **字体重建丢失布局语义。** 旧实现重建为 CFF，丢失 GPOS/GDEF，且只重写部分 GSUB 规则。实际 Arial 和阿拉伯文样本的排版位置与原字体不一致。现在由 HarfBuzz 处理布局依赖和子集，FontTools 仅维护字体名称，保留 TrueType/CFF 原始轮廓类别。
2. **同一 glyph 的多个 Unicode 映射丢失。** 原来只给每个 glyph 保留一个 code point。补充共享 glyph 的 cmap 回归，新引擎保留所有需要的映射。
3. **ASS 样式布尔值错误。** `Bold=-1`、`Italic=-1` 被识别为关闭。现在遵循样式非零为真的规则；裸 `\b`、`\i` 恢复当前样式。
4. **SSA 和字幕结构兼容性。** 支持 `[V4 Styles]`、大小写不同的节名、缺省 Format、样式与事件之间的其他节。字体别名重写使用同样的节识别规则。
5. **绘图和空白误收集。** `\p` 绘图不再当文字；`\h` 收集不换行空格；`\n` 根据 WrapStyle 收集空格或换行；保留事件尾部空格。
6. **变换状态和样式重置。** 解析带括号的 override，保守保留变换两端需要的字体状态，避免括号进入字体名；限制状态数，防止组合爆炸。
7. **别名与附件冲突。** 别名纳入字体字符集合；同一名称、同一实际字体面上的多个请求字重合并字符后生成一个附件。不同轨道字符集合不再默认得到相同别名。
8. **静默漏报字符。** 不再把整个标点、货币、数学符号区段排除在缺字报告之外；严格模式遇到缺字或生成失败返回空结果。仅控制字符和 Unicode 默认可忽略字符免于独立缺字警告。
9. **缓存过期内容。** 字体目录变更使旧缓存失效；并发相同输入合并计算；超过容量的结果不会先挤空缓存。
10. **SRT 默认不可用。** 未指定自定义样式时使用 Arial 默认样式，提供了其中一半配置时明确报错；补充下划线和常见 HTML 实体转换。SRT 输出写为 ASS。

### 资源、存储和接口

11. **批次限额无法约束多请求。** 原并发仅限单个批次，多请求会成倍增加工作量。现在全局准入发生在读取请求体之前，批次内部依次执行，超额请求返回 503 和 Retry-After；包括无 Content-Length 的流也受体积限制。
12. **CPU 字体计算阻塞服务线程。** 字体计算移至独立进程：每进程 512 MiB 地址空间、30 秒 CPU、HarfBuzz 单次 20 秒、整次 worker 60 秒；生成字体和嵌入数据另有总量上限。
13. **字体名称查询全表扫描。** 新增 NFKC/空白/连字符统一归一化字段及索引，避免在 WHERE 中逐行处理 11 万条名称。
14. **字体统计和扫描浪费。** 根目录文件数不再递归重复计算全部子目录；统计缓存 30 秒；空 keys 明确表示空任务；直接读取 name/OS/2/head，无需为建立目录解析全部 OpenType 布局。
15. **同名上传覆盖已有文件。** 管理和成员上传统一走内容寻址、去重路径，保留已有字体；本地写入使用同目录临时文件后 rename。
16. **路径约束不完整。** 字体访问拒绝路径中的符号链接；待审核文件删除必须位于独立归档目录内，不能误删根目录。
17. **归档检查不完整且重复执行。** 去掉自写 ZIP 中央目录扫描器，使用维护中的 7z 读取 ZIP/ZIP64/7z，单次检查限制输出、文件数、解压总量和执行时间。拒绝绝对路径、父目录跳转、链接、加密包、损坏包和被禁止的文件类型；7z 中的危险路径不再被静默跳过。
18. **审核和灾备并发。** 审核时重新校验包内容；同进程内 manifest 写入按顺序生成当前快照，避免较旧写入覆盖较新写入。
19. **错误响应不明确。** 非法 JSON、表单或 Zod 配置返回 400，体积错误保留 413 或 v2 X-Code；限制 X-Message 大小，避免大量缺字撑破反向代理响应头。
20. **运行清理和关闭。** 运行中定期清理日志/限流桶；停止时先停止接收新请求并等待当前请求，再关闭 SQLite；Docker 设置日志轮转、进程数限制和 no-new-privileges。

### CLI、Web 和交付

21. CLI 的 `10n+1` 文件尾批现在使用单文件二进制协议；批量结果数量、次序、base64 和成功响应数据均校验。
22. CLI 不再忽略批量落盘错误；使用临时文件、sync 和原子替换；严格模式不写 warning 结果；输出重名在发请求前拒绝；密钥显示不再按 UTF-8 字节截断，也不回显新设置的完整密钥。
23. Web 的多次投递共享并发队列；移除文件、清空和卸载页面会取消当前任务；重试不会重复调度处理中任务；同名文件使用独立 ID，ZIP 下载避免重名覆盖。
24. Web 不再把网关错误页面作为字幕下载；直接提交 File 减少前端复制；静态资源路径独立于启动目录，带内容哈希的资源长期缓存。
25. 移除已经不用的 888 行 OpenType 重建实现；服务端 bundle 从基线约 1.46 MB 降至约 0.99 MB。Docker 排除 Rust target、测试、文档和环境文件，使用独立 FontTools 环境，避免发行版 FontTools 包引入不需要的科学计算依赖。
26. `bun audit` 发现 Hono 4.13.5 的 GHSA-hxh3-vqpv-xpqv；锁文件升级到 4.13.7，复查 169 个包未发现已知漏洞。此结果不涵盖 Rust、系统软件和未来公开的漏洞。
27. 新增 main/PR 自动检查和三平台 CLI 测试。部署脚本使用缓存构建、互斥锁、Git 版本标签、SQLite 在线备份、健康验证及旧镜像回滚。

## 验证与测量

### 自动检查

- 基线：29 个 Bun 测试、2 个 Rust 测试通过，类型检查和构建通过。
- 修复后：52 个 Bun 测试、4 个 Rust 集成测试通过；workspace 类型检查、Web 和服务端构建通过。
- Chromium 浏览器检查 9 个页面路由，无未捕获页面错误；重复同名字幕显示为 2 条并均处理成功，390 px 移动端没有横向溢出。
- Docker 中使用 Bun 1.4.0、HarfBuzz 10.2.0、FontTools 4.62.1；实际容器完成字幕接口和字形对比。
- 回归包含严格缺字、SSA、绘图、空白、变换、竖排、连字、共享 cmap、缓存失效、并发准入、流式请求体、归档和路径越界、CLI 尾批与输出冲突。

### 真实字体

使用本机字体库中的 Arial、Microsoft YaHei、思源黑体和 DejaVu Sans，构造拉丁文、中日韩、竖排、阿拉伯文字幕。提取生成的字体，用 `hb-shape` 比较 glyph 的位置、advance 和 cluster，并用 FontTools 比较展开组件后的轮廓。

| 样本 | 旧实现的位置/轮廓均一致 | 新 Docker 容器的位置/轮廓均一致 |
| --- | --- | --- |
| 拉丁文 | 否 | 是 |
| 中日韩 | 否 | 是 |
| 竖排 | 是 | 是 |
| 阿拉伯文 | 否 | 是 |

TrueType 转 CFF 本身也会改变轮廓记录形式，因此旧实现的轮廓差异不能单独等同于视觉损坏；Arial/阿拉伯文的位置差异则直接证明排版语义不一致。Microsoft YaHei 缺少样本中的韩文，两个版本都报告缺字；测试没有把缺字字体误标为完整覆盖。

### 性能取舍

12 次只读查询的中位数：同一个迁移后的 11 万名称数据库上，旧扫描约 44.456 ms，新索引约 0.004 ms。EXPLAIN QUERY PLAN 确认从 SCAN 变为 `idx_font_names_normalized` 索引搜索。这是缺失名称查询的微基准，不代表整体请求吞吐量提升相同倍数。

| 指标 | 旧生产容器 | 新构建的验证容器 |
| --- | ---: | ---: |
| 4 组样本冷处理 | 20–113 ms | 111–221 ms |
| 成功结果命中缓存 | 1.39–2.25 ms | 1.32–2.11 ms |
| 处理期间健康接口最大耗时 | 79.84 ms | 7.27 ms |

每次启动原生进程并保留完整所需布局、hinting，增加了冷处理耗时和部分输出体积。4 组子集字体仍比完整源文件小约 96.4%–99.93%；该比例仅代表本次样本。新实现优先保持排版和服务响应性，没有声称单次冷处理更快。低延迟 worker 池需要额外的生命周期、隔离和内存压测，本次未引入。

原始测量文件位于 [measurements](measurements/)。复查命令：

```bash
bun run check
cargo test --locked --manifest-path cli/Cargo.toml
bun audit
bun scripts/benchmark-subset.ts http://127.0.0.1:3300 /tmp/fontinass-benchmark
python3 scripts/verify-shaping.py /tmp/fontinass-benchmark
python3 scripts/benchmark-lookup.py data/fontinass-v2.db
```

基准会产生普通处理日志。数据库查询和字形对比只读取源字体/数据库。不能把同一台主机的短时样本视为容量或可用性承诺。

## 部署与恢复

1. 提交并推送 main，设置 3 GiB 容器的并发为 2、字幕单文件 8 MiB、单批 32 MiB。已有 `.env` 需要显式调整。
2. 执行 `./rebuild-and-start.sh`。脚本在切换前使用 SQLite `VACUUM INTO` 生成一致性备份，备份包含 WAL 中已提交的数据。
3. 脚本检查健康响应和镜像上的 `org.opencontainers.image.revision`。失败时恢复旧镜像；本次数据库迁移是新增列/索引，旧版查询仍可读取。
4. 复查本地和公开域名的健康接口、实际字幕请求、严格缺字结果、静态资源以及容器日志。单凭 Docker 命令成功不能判断部署完成。
5. 需要手动回滚镜像时使用 `FONTINASS_IMAGE_TAG=rollback docker compose up -d --no-build --force-recreate`，随后重新验证。恢复数据库备份需要先停止写入；不要在服务仍写入时直接覆盖 DB/WAL 文件。

## 剩余边界

- 未对 31,504 个字体文件逐个做全部字符、全部布局特性的渲染验证；可变字体、彩色字体、复杂脚本、极端特效与不同播放器的差异仍需要扩大语料。
- 无 BOM 的旧编码仍有歧义，解码保留既有 UTF-8/UTF-16/Latin-1 路径；未加入可能误猜 GBK/Shift-JIS 的自动检测。
- R2 和 SQLite 不具备跨服务事务。已串行化 manifest 写入，但对象上传、元数据更新、网络失败和进程崩溃之间的原子性仍需要独立 outbox/恢复设计；本次未改写现有 186 个已发布归档。
- 限流依赖入口代理正确覆盖客户端 IP 头；服务仅绑定 localhost。多实例部署还需要共享资源准入和 manifest 锁，本次范围是现有单容器部署。
- 保留了 `API_KEY` 为空时开放管理的既有行为。已设置密钥的当前部署不受影响；新部署应按 README 配置。
- 根 LICENSE 为 AGPL-3.0，CLI 的 Cargo 元数据与 README 声明 MIT。是否属于有意的双重授权需要仓库所有者明确，本次没有擅自改变已有许可证。

## 参考项目

参考并读取了以下公开项目的实现与说明，未复制其业务代码：

- [assfonts](https://github.com/wyzdwdz/assfonts)：ASS 字体收集、HarfBuzz 子集化、命名与多字体合并思路，重点阅读 `lib/ass_parser.cc` 和 `lib/font_subsetter.cc`。
- [HarfBuzz](https://github.com/harfbuzz/harfbuzz)：原生子集化和布局依赖闭包，阅读 `util/hb-subset.cc` 并核对 CLI 参数。
- [FontTools](https://github.com/fonttools/fonttools)：sfnt/CFF 名称维护、字体读取和字形验证，阅读 subset 实现并使用 TTFont API。
- [libass](https://github.com/libass/libass)：SSA/ASS 默认格式、样式布尔值和 override 的实际渲染语义，阅读 `libass/ass.c`、`libass/ass_parse.c`。
